# DataMind Agent 路线图

> **口径**：本路线图只承诺"可测的完成条件"，不承诺日期与百分比。
> 所有阈值来自仓库内已实测读数（见 [性能](PERFORMANCE.md) 与 [进度](../PROGRESS.md)）；
> 没有实测的能力只写"待测量"，不预先给数字。

## 0. 当前基线

任何里程碑的验收都从这里出发，不允许"看起来更快了"。

| 项 | 基线值 | 说明 |
| --- | --- | --- |
| 代码 API | 0.39.0 | `datamind/api.py` 的 `FastAPI(version=…)` |
| 完整隔离回归 | 1658/1658 | **最近存档的全量执行口径**；是否全绿只看机读记录的 `failures`/`errors`，不看 N/N 写法 |
| 文档问答工具链预热 p95 | 114.059 ms（n=11） | 不含模型；[性能](PERFORMANCE.md) §6 |
| 混合检索预热 p95 | 36.267 ms（n=11） | 冷启动 373.572 ms，主要差在嵌入模型加载 |
| 三表 JOIN 聚合 @10 万行 p95 | 75.141 ms | 单机、无 CPU 绑定；[性能](PERFORMANCE.md) §3 |
| 词法打分 @5000 切片 p50 | 470.407 ms | 当前检索主瓶颈，复杂度仍为 O(n)；[性能](PERFORMANCE.md) §4.2 |
| SQL 工具链并发 8 吞吐 | 195.97 次/秒（成功率 100%） | 每格只重复 1 次，非生产吞吐承诺 |
| 每轮重复建连 p50 | 4.883 ms | 尚无连接池；[性能](PERFORMANCE.md) §6 |

数据侧现状：27 份文档资产、169 切片/向量、23 条候选事实（2026-10-08 清理后实测，见 [进度](../PROGRESS.md)）。
所有数字都带适用范围，跨阶段不可拼接。

## 1. 优先级排序与理由

1. **可信 > 覆盖 > 性能 > 观感**。一个能被复核的窄能力，比一个说不清来源的宽能力有价值。
2. **先收口已建成的东西**。仓库里已有解析契约、证据图、Wiki、私有 PDF 五条较完整的链路，
   但对外叙述与文档入口没跟上；这属于"零新增能力、高感知收益"的工作，必须排第一。
3. **再补核心闭环的最后一公里**。多轮历史、引用展开、检索瓶颈是用户每天都会碰到的路径。
4. **然后才是知识沉淀的规模问题**。Wiki 回填与跨源冲突依赖真实材料，强行提前只会造假边界。
5. **部署与规模化放最后**。当前形态是本机回环演示，在没有真实并发用户前优化容量是猜测。

## 2. M0 口径收口与可信基线

**目标**：让仓库读起来是一个自洽的自有产品项目——能力、边界、证据三处说法一致，
文档入口没有断链，回归基线可复核。

**交付物**

- 产品定义与路线图（[PRODUCT.md](PRODUCT.md)、本文件）。
- README、PROGRESS、`docs/`、`技术文档/` 的对外叙述统一：只描述本产品自己的目标、能力与边界。
- 清理历史文档中指向已删除文件的入站引用，保证链接检查 0 断链、导航表不含死链。
- 能力矩阵与文档导航补齐：Wiki、证据图、私有 PDF 三条链路在主导航里可见。
- 禁用词扫描词表落库（词表单独存放，避免词表本身出现在产品文档里）。

**验收口径**

- 禁用词扫描：`docs/`、`技术文档/` 与根目录 Markdown **0 命中**。
- 相对链接检查：0 断链；抽查 5 条能力条目，其"证据位置"均指向存在的文件。
- `scripts/verify.py` 退出码 0；`scripts/test_isolated.py` 的 `failures`/`errors` 均为 0。
- `scripts/status_sync.py --check` 无漂移；API 版本与前端缓存版本一致。
- 回归分母若因新增测试变化，必须在本文件 §0 与 [进度](../PROGRESS.md) 同步更新。

**依赖与风险**

- 依赖并行改动收敛；文档口径统一涉及多人，需以"能力状态只认证据文件"为裁决规则。
- 风险：把"改措辞"做成"改事实"。约束是只改口径，不动实测数字与结论。

## 3. M1 核心闭环可用性

**目标**：把"问一次、看一眼"的路径补完整——历史可用、引用可展开、检索不再是线性瓶颈。

**交付物**

1. **前端多轮**：提问请求携带 `history`，展示 `turns_used`；不传历史时提示词逐字节不变（既有守护必须保留）。
2. **引用可展开**：引用卡片展示原文与页码/区域；只渲染存储中确有的定位，旋转页与非页面定位只显示标签。
3. **检索候选剪枝或倒排索引**：把词法打分从"全量逐行"改成"先廉价过滤再打分"，
   或把输入换成倒排候选集；无论走哪条，都必须保持候选集与 top-5 可比。
4. **问数泛化验收**：在未参与开发的只读 schema 上跑一次 schema linking 与 SQL 生成，
   记录失败类型，不修改既有断言。
5. **错误码到界面的一致映射**：新增错误码必须有中文解释与可操作提示。

**验收口径**

- `tests/test_multi_turn.py`、`tests/test_frame_multi_turn.py` 全绿；`turns_used` 与实际传入条数一致。
- `tests/test_frontend_locators.py`、`tests/test_rag_locators.py` 全绿；PDF 路径返回的定位条数 > 0（对确有定位的文档）。
- 检索 @5000 切片 p50 **不高于 470.407 ms**；优化落地后用同口径复测，并把新读数写回 [性能](PERFORMANCE.md)。
- 工具链预热 p95 **不高于 114.059 ms**；三表 JOIN @10 万行 p95 **不高于 75.141 ms**（回归守门，不允许劣化）。
- 问数泛化：记录题量与失败类型；**不以一次小样本推断准确率**。

**依赖与风险**

- 依赖 [多轮契约](MULTI_TURN.md) 与 [性能](PERFORMANCE.md) §4.2 的测量级原型。
- 风险：倒排索引会改变 BM25 的长度均值，分数不可逐位对齐；验收只要求候选集与 top-5 可比，
  不要求分数相同。
- 风险：上游模型波动会让"同一题两次不同结果"，因此 M1 的验收一律用确定性用例或固定题集。

## 4. M2 知识沉淀与跨源

**目标**：让问答产物真正沉成知识——可回填、可复核、可追溯版本，冲突有落点。

**交付物**

1. **Wiki 受控回填（P5）**：历史运行先 dry-run，输出归属、候选词条、无法归一项与缺失出处；
   确认后分批回填候选草稿，不自动发布历史主张。
2. **跨源冲突落库**：跨源核验的冲突记录进 `conflict_records` 并可查询，
   不再只存在于运行终态里。
3. **来源换版提示**：来源版本变化后词条标"待重新核验"，并能查看旧版本与重核结果。
4. **中文正文检索策略**：明确第一版只覆盖标题/别名/分类，还是引入正文索引；结论写进契约。
5. **权威登记范围**：至少覆盖一类真实冲突（单位、版本、记录对象），双方原值都保留。

**验收口径**

- 回填 dry-run 报告字段齐备；同一请求重复执行**不产生重复词条**（幂等断言）。
- 回填后原有问答与审计链不变：既有回归全绿，停用 Wiki 入口不影响问答。
- 跨源冲突：`conflict_records` 可按来源查到双方原值与裁决依据（当前库跨源运行 0 次，
  这条验收必须先造出至少一次真实跨源运行）。
- 来源换版：`source_validity='stale'` 由**真实样本**触发，而非仅靠合成用例。
- 权限：非回环来源 + 真实账号下，viewer/reviewer/approver 三档行为符合 [接口契约](WIKI_API.md) §3。

**依赖与风险**

- 依赖真实材料（换版文档、跨源冲突样本）。拿不到就**另立分母**，不复用合成材料成绩。
- 风险：`evidence_edges` 线上形状比迁移窄，边理由与置信度没有落库；历史数据只能标
  `provenance_incomplete`，不得推测补全（见 [领域契约](WIKI_DOMAIN.md) §1.1）。
- 风险：回填是批量写操作，必须可停、可回退、可核对导入/跳过/失败原因。

## 5. M3 部署与规模化

**目标**：把"本机演示"推进到"可交付给一个真实小团队试用"，仍然不承诺生产 SLA。

**交付物**

1. **连接池**：消除每轮重复建连；问数与检索共用同一池化入口。
2. **解析 worker 队列**：PDF/OCR 接入独立 worker，按保守上限起步（解析 2 / OCR 1 / 公式 1 / 嵌入 1），
   批次内单文件失败不影响其他文件。
3. **跨主机租约**：把 `task_leases` 接进执行路径，替换"同主机进程组"假设。
4. **可观测**：`/health` 分层（服务 / 数据库 / 向量库 / 模型连通性分开），日志不落密钥。
5. **迁移权威收敛**：`deploy/init` 与 `db/migrations` 的表形状统一，明确谁是权威。

**验收口径**

- 建连 p50 **低于 4.883 ms**，并在 [性能](PERFORMANCE.md) §6 留下复测读数。
- 并发 8 档成功率保持 1.0；吞吐**不低于 195.97 次/秒**（同机同口径；环境不同只记录不判定）。
- 20 文件批次：部分失败时逐项状态正确，重试不重复登记成功项。
- 重启后任务从数据库恢复，不依赖内存状态。
- 迁移：升级库与新建库得到同一形状，且有测试钉住。

**依赖与风险**

- 依赖 M0 的基线可信；基线不可信时任何"变快了"都无法判断。
- 风险：CPU/内存硬隔离在当前平台不完整（macOS 不支持 `RLIMIT_AS`，已失败关闭）；
  容量类结论必须写清"非 cgroup 口径"。
- 风险：跨主机租约涉及一致性问题，宁可保持"单机、明确声明"，也不要半实现的分布式。

## 6. 明确不追的指标

以下项目**不进入**任何里程碑的验收，避免团队被数字带偏：

- **模型榜单分数**：不追公开基准排名；阶段读数（如单轮问答、规则核验的通过数）只作回归，
  不拼成"产品准确率"。
- **端到端 P95**：生成段受上游与网络支配，仓库只记录观测值（如模型段 p50 1674.2 ms / p95 3238.6 ms），
  不作产品承诺。
- **并发吞吐卖点**：195.97 次/秒是单机单轮工具链读数，不写到对外材料里当容量结论。
- **文档页数吞吐**：解析约 85 ms/页由位图渲染主导，优化它会改动解析行为，收益与风险不匹配。
- **格式覆盖率**：不追 DWG/三维/更多 Office 特性的"支持数量"，只追已支持格式的边界诚实。
- **全自动知识治理**：不做自动权威判定、自动实体归并、自动冲突裁决。
- **新基础设施**：第一版不引入图数据库、不新增第二套向量链路。

## 7. 依赖关系与并行建议

```text
M0 口径与基线
 ├──► M1 核心闭环可用性 ──► M2 知识沉淀与跨源
 └──► M3 部署与规模化（可与 M1/M2 并行，共用 M0 基线）
```

- M0 是所有里程碑的前置：基线不成立时，后续"改进"无法度量。
- M1 与 M3 可以并行（一个改产品路径，一个改运行形态），但两者都要跑同一套回归。
- M2 的回填与 M3 的队列有耦合：回填是批量任务，最好复用 M3 的 worker 与幂等原语。

## 8. 变更控制

1. **阈值只能被新实测替换**：替换时必须同时更新本文件 §0、对应里程碑的验收口径，以及该读数的来源文档。
2. **新增能力先进 [能力矩阵](PRODUCT.md)**，状态为"未做/部分"的能力不得在路线图里被写成已完成。
3. **里程碑不合并**：M1 未达标不进入 M2 的验收；可以先做 M2 的调研，但不能宣称完成。
4. **失败也算交付**：被实测否掉的方案（如块定位批量取回 ×0.79）要留在 [性能](PERFORMANCE.md) 里，
   避免下一轮重复试错。
